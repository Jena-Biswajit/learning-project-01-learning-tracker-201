### What is Maven?
- **Maven** is a build **automation** and project management tool for Java projects. 
- It simplifies project setup, **dependency management**, **compilation**, **testing**, and **deployment**.

### Why Use Maven?
- **Automates** build process (compile, test, package, deploy)
- **Manages dependencies** (resolves and downloads required libraries)
- Follows a standard project structure
- Works with multiple Java frameworks (Spring, Hibernate, Servlets)
- **Integrates** with CI/CD tools (Jenkins, Docker, Kubernetes)

### Key Features of Maven
- **Project Object Model (POM)**
  - pom.xml is the heart of a Maven project, defining dependencies, plugins, and configurations.

- **Dependency Management**
  - Automatically downloads required JAR files from the Maven Central Repository.

- **Build Lifecycle**
  - Executes phases like compile, test, package, and install.

- **Plugins & Extensions**
  - Extends functionalities (e.g., maven-compiler-plugin, maven-surefire-plugin).

- **Multi-Module Support**
  - Manages large projects with submodules.

- **Maven Build Lifecycle**
```
- mvn clean install
```
- **clean →** Removes old build files.

- **compile →** Compiles Java files.

- **test →** Runs unit tests.

- **package →** Creates a .jar or .war file.

- **install →** Installs the package in the local repository.

### How Maven Manages Dependencies?
  - Instead of manually adding JAR files, just include them in pom.xml:
```
<dependencies>
<dependency>
<groupId>org.springframework</groupId>
<artifactId>spring-core</artifactId>
<version>5.3.20</version>
</dependency>
</dependencies>
```
- Maven downloads and manages the required JAR files automatically.

### How to Create a Maven Project?

```
- mvn archetype:generate -DgroupId=com.example -DartifactId=myapp -DarchetypeArtifactId=maven-archetype-quickstart -DinteractiveMode=false
This generates a standard Maven project structure.
```

### Where is Maven Used?
  - Web applications (Servlets, JSP, Spring Boot, Hibernate)
  - Microservices & cloud applications (Docker, Kubernetes)
  - Automated CI/CD pipelines (Jenkins, GitHub Actions)



### Maven Project Structure

**Standard Directory Layout**

- Maven follows a convention over configuration principle, meaning it expects projects to follow a standard structure. 
- This makes projects easier to manage, build, and share.

### Why is Maven Structured This Way?

**1. Separation of Concerns**

- **src/main/java/ →** Main application code.

- **src/main/resources/ →** Configuration files (e.g., application.properties, XML files).

- **src/test/java/ →** Unit tests, making test management easy.

**2. Standardization & Portability**

- Any developer familiar with Maven can instantly understand the project.
- Tools like Jenkins, GitHub Actions, and Docker work smoothly with this structure.

**3. Automated Build & Dependency Management**

- **pom.xml →** Defines dependencies, plugins, and build lifecycle.
- **mvn package →** Compiles, tests, and packages the code automatically.

**4. Web Application Support (for Servlets, Tomcat, Spring Boot)**

- **src/main/webapp/ →** Required for servlet-based applications (JSP, HTML, CSS, JS).
- Can be deployed to **Tomcat**, **Jetty**, or **WildFly** easily.

**5. Efficient Testing & Deployment**

- **src/test/java/** ensures all test cases are separate from the main code.
- **target/** stores compiled .class files, JARs, and WARs, avoiding clutter in the main directory.

### What Happens During Build?

**When you run:**

```
- mvn clean install
```
**Maven Steps in the Build Lifecycle:**

- **clean →** Deletes target/ directory.

- **compile →** Converts .java into .class files.

- **test →** Runs unit tests using JUnit or TestNG.

- **package →** Creates a .jar or .war file inside target/.

- **install →** Stores the packaged file in the local repository (~/.m2/repository/).

```

 ┣ 📂 src
 ┃ ┣ 📂 main

```
